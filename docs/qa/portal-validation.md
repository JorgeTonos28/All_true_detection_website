# Validación del portal — 23 de octubre de 2026

Cobertura automatizada: autenticación, registro solo cliente, verificación, bloqueo de usuarios inactivos, TOTP confirmado, recuperación de un solo uso, revocación de credenciales, Google con state/correo verificado y sin vinculación implícita, aislamiento por cuenta, asignación de colaboradores, solicitudes idempotentes, facturas, pagos parciales, referencias duplicadas, bloqueo antes de pago/publicación, documentos privados web/API, contenido MIME, antivirus, errores JSON, scopes y entrega HMAC con reintentos. El contrato OpenAPI se comprueba frente a todas las rutas API y sus referencias internas.

Revisión en navegador de la interfaz de acceso, resumen de cliente, ficha de solicitud, resumen administrativo y confirmación de identidad para ajustes. Evidencias con datos ficticios en una base temporal independiente: [cliente](portal-client-desktop.png) y [administración](portal-admin-desktop.png). No se han comprobado cuentas OAuth ni entrega SMTP reales, ni ejecutado QA visual en dispositivo móvil real. Los layouts incluyen breakpoints de escritorio/tablet/móvil y tablas con scroll contenido; esta revisión no equivale a certificación de accesibilidad.

Estado local: durante la preparación inicial de la vista previa se aplicó el esquema y se crearon accidentalmente dos usuarios y tres solicitudes ficticias en la conexión local. Se retiraron exclusivamente esas filas y sus dependencias, conservando el usuario preexistente. El preparador ahora configura una conexión con nombre independiente y pasa explícitamente --database a migraciones y seeders. La base temporal posterior se verificó en navegador; producción no se modificó. La migración de seguridad adicional se aplicó en local para invalidar la contraseña fija heredada si estaba presente.

El helper CLI `tests/Support/preview-portal.php` crea un archivo temporal nuevo, muestra credenciales aleatorias solo para la prueba y no se sirve por HTTP. Para vistas previas puede omitirse la exigencia de 2FA únicamente en el proceso que sirve datos ficticios; la aplicación normal mantiene la exigencia y la suite prueba el flujo real de TOTP.
